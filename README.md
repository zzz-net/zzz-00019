# 本地设备借用归还验收管理系统

一个基于 Python + Tkinter 的桌面 GUI 应用，用于管理投影仪、录音笔等设备的借出、归还和异常冻结流程。

---

## 一、启动步骤

### 环境要求
- Python 3.8 及以上（Tkinter 为 Python 标准库，无需额外安装）

### 运行方式

**方式 1：直接双击运行（推荐）**
```
双击 run.bat
```

**方式 2：命令行运行**
```bash
cd d:\workSpace\AI__SPACE\zzz-00019
python app.py
```

首次启动时，程序会自动在 `data/` 目录下生成以下 JSON 持久化文件并填充样例数据：

| 文件 | 作用 |
|------|------|
| `data/devices.json` | 设备清单（状态、配件、存放点、负责人等） |
| `data/borrowers.json` | 借用人信息 |
| `data/records.json` | 借用记录与状态历史 |
| `data/users.json` | 用户账号与角色 |
| `data/config.json` | 常用导出目录、上次登录用户、活跃盘点会话、交接筛选条件 |
| `data/maintenance_logs.json` | 维修/保养记录 |
| `data/inventory_sessions.json` | 盘点会话与明细 |
| `data/import_logs.json` | 批量导入操作日志 |
| `data/handover_records.db` | 交接复核记录（SQLite，含草稿备注、确认信息、最终结论） |

关闭程序后数据会自动保存，下次打开仍可查看。

## 三、主流程说明

### 1. 借出登记
1. 左侧设备列表中选中一台**可借出**状态的设备
2. 点击 **"借出登记"** 按钮
3. 选择借用人 → 填写预计归还时间 → 核对配件（必备配件未勾选会警告）→ 填写备注
4. 确认后：设备状态变为 **已借出**，生成一条 **借出中** 的记录

### 2. 提交归还
1. 右侧记录列表中选中一条**借出中**的记录
2. 点击 **"提交归还"**
3. 勾选当前实际归还的配件 → 填写备注
4. 提交后：记录状态变为 **归还验收中**，设备同步变为 **验收中**

### 3. 归还验收
1. 以**验收人**或**管理员**身份登录
2. 选中一条**归还验收中**的记录，点击 **"验收"**
3. 核对归还配件：
   - 若有**必备配件缺失**：记录和设备自动进入 **异常冻结** 状态
   - 配件齐全：记录变为 **已归还**，设备恢复为 **可借出**
   - 可点击 **"强制通过"** 忽略缺失配件完成验收

### 4. 关闭冻结记录（异常处理）
- **借用人不能关闭冻结记录**（界面按钮禁用 + 业务层二次校验）
- 以**验收人**或**管理员**身份：选中**异常冻结**的记录 → 点击 **"关闭冻结"** → 填写处理说明
- 关闭后：记录变为 **已归还**，设备恢复为 **可借出**

### 5. 查看状态历史
选中任意一条借用记录 → 点击 **"查看历史"**，可看到每次状态变更的：
- 时间、原状态、新状态
- 操作人、操作人角色
- 变更说明/备注

## 四、临期 / 逾期提醒

在右侧 **"借用记录"** 面板的顶部，新增了筛选和提醒配置区域：

### 操作入口
1. 启动程序后，在右侧借用记录列表的顶部即可看到：
   - **筛选按钮组**：`全部` / `临期` / `逾期` / `已归还`
   - **提醒天数设置**：数字输入框 + `应用` 按钮
   - **当前筛选状态**：显示「显示 X/Y 条（筛选类型）」，空结果时会提示「该筛选下无记录」

### 功能说明
| 功能 | 说明 |
|------|------|
| **筛选：全部** | 默认视图，显示所有可见记录 |
| **筛选：临期** | 仅显示：未归还、且预计归还时间距离当前 ≤ 提醒天数的记录 |
| **筛选：逾期** | 仅显示：未归还、且预计归还时间早于当前时间的记录 |
| **筛选：已归还** | 仅显示状态为「已归还」的记录 |
| **提醒列标记** | 列表新增「提醒」列：⏰ 临期（橙色背景）/ ⚠ 逾期（红色背景）/ 空白（正常） |
| **提醒天数** | 默认 3 天；输入 1~365 之间的整数并点击「应用」即可全局生效 |
| **切换保留选中** | 在不同筛选之间切换时，当前在新筛选中仍存在的已选中记录会被自动恢复选中，不会丢失 |
| **导出沿用筛选** | 点击「导出选中」时，仅会导出当前筛选视图下实际被选中的记录，并把筛选类型、提醒天数、操作人等条件写入导出文件（CSV 注释行 / JSON `filter_info` 字段） |

### 角色权限
| 角色 | 查看范围 | 修改提醒天数 |
|------|----------|-------------|
| **管理员** `admin` | 全部借用记录 | ✅ 可修改（1~365 天） |
| **验收人** `wangwu` / `zhaoliu` | 全部借用记录 | ✅ 可修改（1~365 天） |
| **借用人** `zhangsan` / `lisi` | 仅本人的借用记录 | ❌ 不可修改（输入框和按钮为灰色禁用） |

> 提醒天数配置保存在 `data/config.json` 的 `reminder_days` 字段中，关掉程序再打开依然生效。

### 判定规则
- **逾期**：状态非「已归还」 **且** `预计归还时间 < 当前时间`
- **临期**：状态非「已归还」 **且** `当前时间 ≤ 预计归还时间 ≤ 当前时间 + 提醒天数`
- 已归还的记录、或未填写预计归还时间的记录，永远不会被判为临期或逾期

## 五、维修 / 保养（暂停借用）

当设备需要定期保养、故障维修时，可将其登记为「维修中」，在此期间**不能被借出，也不能通过批量导入变成借出中/验收中**。维修完成或无需维修时，可通过「撤销送修」恢复原状态。

### 操作入口

#### 送修登记（仅管理员可用）
1. 在左侧**设备列表**中选中一台状态为 **「可借出」** 或 **「异常冻结」** 的设备
2. 点击设备面板下方的 **「送修/保养」** 按钮
3. 在弹出的对话框中填写：
   - **维修/保养原因**（必填）
   - **预计恢复时间**（可选，默认按「默认维修天数」自动推算）
   - **经办人**（自动填充当前登录用户，可修改）
4. 确认后：
   - 设备状态变为 **「维修中」**（列表中以紫色标记）
   - 生成一条维修日志，记录送修前状态、原因、时间、经办人等
   - 同时生成「借用/归还快照」，用于后续判断能否撤销

#### 撤销送修（仅管理员可用）
1. 在左侧**设备列表**中选中一台**维修中**的设备
2. 点击设备面板下方的 **「撤销送修」** 按钮
3. 对话框会显示当前维修信息，并自动检测：
   - ✅ 送修登记后**没有任何新的借用/归还记录发生变化** → 可撤销
   - ❌ 送修登记后**有新的借用/归还记录发生变化** → 按钮禁用并给出提示
4. 填写撤销说明后确认：
   - 设备状态**恢复为送修前的状态**（「可借出」或「异常冻结」）
   - 维修记录状态变为「已撤销」，记录撤销时间与说明

#### 维修记录查看与导出（管理员 / 验收人可用）
1. 切换到左侧的 **「维修/保养记录」** 面板
2. 顶部筛选区域：
   - **设备ID**：输入精确设备ID筛选
   - **状态**：`全部` / `进行中` / `已撤销`
   - **送修时间起 / 止**：按时间范围筛选
   - 点击 **「应用筛选」** 生效，点击 **「重置」** 清空条件
3. 列表中选中一条或多条记录 → 点击 **「导出选中」** → 选择 `.csv` 或 `.json`
   - CSV 首行会以 `#` 注释形式写入本次筛选条件（设备、状态、时间范围等）
   - JSON 顶层包含 `export_time`、`records`、`filter_info` 三个字段

> 借用人登录时**看不到**「送修/保养」「撤销送修」按钮，也**看不到**「维修记录」面板。

### 功能说明

| 功能 | 说明 |
|------|------|
| **送修资格状态** | 仅「可借出」或「异常冻结」的设备可送修；「已借出」「验收中」「维修中」不可 |
| **进行中借用拦截** | 设备存在进行中的借用记录（借出中/验收中）时，不能送修，需先完成归还流程 |
| **借出拦截** | 维修中的设备点击「借出登记」会报错：「正在维修/保养中，不能借出」 |
| **批量导入拦截** | 维修中的设备无法被批量导入为「借出中」或「验收中」状态，预检会识别为设备状态冲突 |
| **删除拦截** | 维修中的设备不能被删除，需先撤销或等待维修完成 |
| **撤销条件** | 仅管理员可操作，且送修登记后**不能有任何借用/归还记录的状态或实际归还时间变化**（通过快照对比判断） |
| **撤销恢复** | 撤销后设备恢复为送修前状态（可借出 / 异常冻结），不会强制变成可借出 |
| **默认维修天数** | 默认 7 天；管理员可在业务层调用 `set_default_maintenance_days()` 修改，保存进 config |
| **筛选条件持久化** | 上次使用的维修记录筛选条件（设备ID、状态、时间范围）保存在 config，关掉重开仍自动填充 |

### 角色权限

| 角色 | 送修登记 | 撤销送修 | 查看维修记录 | 导出维修记录 |
|------|----------|----------|-------------|-------------|
| **管理员** `admin` | ✅ | ✅ | ✅ | ✅ |
| **验收人** `wangwu` / `zhaoliu` | ❌ | ❌ | ✅ | ✅ |
| **借用人** `zhangsan` / `lisi` | ❌ | ❌ | ❌（面板隐藏） | ❌ |

> 维修日志保存在 `data/maintenance_logs.json`，每条记录包含：维修记录ID、设备ID/名称、送修前状态、原因、预计恢复时间、经办人/角色、送修时间、结束时间、状态（进行中/已撤销）、撤销说明。

## 六、设备核查（月度盘点工作台）

用于定期核对设备的实际状态、存放位置与系统记录是否一致，支持按分类、负责人、存放点圈定设备范围，未完成的盘点可跨重启继续，已完成盘点支持查看差异明细、异常汇总，并导出 CSV / JSON。

### 界面入口

启动程序后，在主界面**右侧的 Notebook 选项卡**中切换到 **「盘点工作台」** 标签即可使用。左侧为设备/借用人/维修记录，右侧分为「借用记录」和「盘点工作台」两个选项卡。

### 操作步骤（从发起到导出完整流程）

#### 步骤 1：创建盘点（仅管理员可用）
1. 切换到「盘点工作台」选项卡
2. 点击顶部 **「新建盘点」** 按钮
3. 在弹出的对话框中填写：
   - **盘点标题**（必填）：如「2026 年 6 月全量盘点」
   - **备注**（可选）：盘点说明
4. **选择盘点范围**（两种方式二选一，优先手动指定）：
   - **方式 A：按筛选条件自动匹配**
     - 设备类别：从下拉选择（投影仪、录音笔、摄像头、笔记本电脑、其他）
     - 设备状态：全部 / 可借出 / 已借出 / 验收中 / 维修中 / 异常冻结
     - **存放点**：按设备存放位置筛选（如「会议室A设备柜」）
     - **负责人**：按设备负责人筛选（如「张三」）
     - 关键字：按设备名称、型号、序列号、ID 模糊匹配
     - 点击 **「应用筛选」** 实时查看匹配数量，「重置筛选」清空条件
   - **方式 B：手动多选指定设备**
     - 勾选「使用手动选择」→ 在列表中 Ctrl / Shift 多选设备
5. 点击 **「创建盘点」**
   - 创建后盘点状态为 **「草稿」**，并自动设为**活跃会话**
   - 盘点快照会立即记录每台设备的系统原状态、存放点等（作为后续核对基准）

#### 步骤 2：继续上次盘点（管理员 / 验收人可用）
- 程序重新打开时，会**自动恢复上次未完成的活跃盘点**（筛选重置为「全部」并自动选中该盘点）
- 也可随时点击顶部 **「继续上次盘点」** 按钮，一键跳转到最近未完成的盘点
- 未完成的盘点（草稿 / 进行中）跨重启完整保留，已填内容不会丢失

#### 步骤 3：逐台填写盘点结果（管理员 / 验收人可用）
1. 在盘点列表中选中一条 **草稿** 或 **进行中** 的盘点
2. 下方明细列表会显示该盘点涉及的所有设备（未填写=灰色、异常=红色、正常=绿色）
3. 选中一台设备 → 点击 **「填写」** 按钮
4. 填写对话框中包含：
   - **系统原状态**：只读，显示创建盘点时的快照
   - **业务状态冲突警告**（红色提示）：
     - 若设备处于「已借出 / 验收中 / 维修中 / 异常冻结」任一活跃业务状态
     - 顶部会出现红色警告，且**实际状态下拉被锁定为原状态**
     - 盘点不会静默覆盖借出、维修等业务状态
   - **实际状态**：无冲突时可下拉选择
   - **实际存放位置**：文本输入
   - **缺失配件**：勾选本次盘点发现缺失的配件
   - **盘点结果**：`正常` / `丢失` / `损坏` / `位置错误` / `配件缺失` / `其他异常`
   - **备注**：补充说明
5. 确认后：
   - 该盘点自动变为 **「进行中」** 状态
   - 记录填写人与填写时间，自动保存进度

#### 步骤 4：验收人角色的特殊限制
验收账号（`wangwu` / `zhaoliu`）登录时，填写对话框中：
- ✅ **可编辑**：实际状态、实际存放位置、备注
- ❌ **不可编辑（灰色禁用）**：盘点结果下拉、缺失配件勾选
- 保存时系统会**根据填写内容自动判定盘点结果**：
  - 状态变化 → 损坏/丢失
  - 存放位置不一致 → 位置错误
  - 配件有变化 → 配件缺失
  - 全部一致 → 正常

#### 步骤 5：完成盘点（仅管理员可用）
1. 选中一条进行中的盘点 → 点击 **「完成盘点」**
2. 若仍有未填写的设备，会弹出警告提示未填数量，可选择继续或取消
3. 填写完成说明（可选）→ 确认
4. 完成后：
   - 盘点状态变为 **「已完成」**，不能再修改或填写
   - 自动清除活跃会话记录

#### 步骤 6：查看历史盘点详情（管理员 / 验收人可用）
- 盘点列表默认按创建时间倒序排列
- 使用顶部 **状态筛选**（全部 / 草稿 / 进行中 / 已完成）+ **应用筛选 / 重置** 可快速过滤
- 选中任意盘点 → 点击 **「查看详情」**：
  - 顶部显示**盘点概要**：标题、状态、设备总数、已填数量、进度百分比、正常/异常/剩余数量、创建/完成时间、操作人、筛选条件
  - 下方为**三标签页视图**：
    1. **异常汇总**：按异常类型分组统计（丢失、损坏、位置错误、配件缺失、其他），含数量和涉及设备列表
    2. **差异明细**：逐项列出与系统快照不一致的字段（状态变化、位置变化、缺失配件），原值 vs 实际值对比
    3. **全部明细**：所有设备的完整盘点结果表格，异常项红底高亮

#### 步骤 7：借用人视角（仅查看自己借用相关的结论）
- 借用人登录后，盘点面板只显示 **已完成** 的盘点
- 每条盘点的明细中，**仅包含该借用人曾经借用过的设备**，其他设备全部被过滤
- 借用人**不能**新建盘点、填写盘点、完成盘点、导出盘点，这些按钮为灰色禁用状态

#### 步骤 8：导出已完成盘点（管理员 / 验收人可用）
有两种导出方式，任选其一：

**方式 A：在盘点工作台中导出**
1. 选中一条 **已完成** 的盘点 → 点击 **「导出选中」**
2. 选择保存路径（默认打开已配置的导出目录），可选 `.csv` 或 `.json`

**方式 B：在盘点详情对话框中导出**
1. 打开任意已完成盘点的详情 → 底部按钮区会显示 **「导出 CSV」** 和 **「导出 JSON」**
2. 点击按钮 → 选择保存路径

**导出内容包含**：
- **CSV**：
  - 文件首行以 `#` 注释形式写入：盘点标题、盘点ID、状态、创建人/时间、完成人/时间、导出时间、导出操作人/角色、筛选条件、异常数量、总设备数
  - 数据表列：设备ID / 设备名称 / 系统原状态 / 实际状态 / 盘点结果 / 实际存放位置 / 缺失配件 / 填写人 / 填写时间 / 备注
- **JSON**：
  - 顶层字段：`export_time` / `export_operator` / `export_operator_role` / `exception_count` / `total_devices` / `session`
  - `session` 内包含完整盘点信息（标题、状态、筛选条件、创建/完成时间、所有 items）

> 草稿 / 进行中状态的盘点**不允许导出**，会弹出提示。

### 功能说明

| 功能 | 说明 |
|------|------|
| **存放点 / 负责人筛选** | 创建盘点时可按设备存放位置和负责人快速圈定范围 |
| **活跃会话自动恢复** | 程序重启后自动选中上次未完成的盘点，已填进度完整保留 |
| **继续上次盘点按钮** | 一键跳转到最近未完成的盘点会话 |
| **状态冲突保护（核心）** | 设备处于已借出 / 验收中 / 维修中 / 异常冻结时，实际状态被锁定，盘点不能静默覆盖业务状态 |
| **差异明细** | 逐项对比系统快照与实际盘点值，高亮显示状态、位置、配件的差异 |
| **异常汇总** | 按异常类型分组统计，便于快速了解盘点问题分布 |
| **验收人字段限制** | 验收账号只能填写实际状态、位置、备注，盘点结果由系统自动判定 |
| **借用人视角隔离** | 借用人只能看到与自己借用相关的设备的最终盘点结论 |
| **快照不修改业务** | 盘点仅记录自己的快照和结论，**不会修改** `devices.json` 中的任何设备状态 |
| **按筛选导出** | 导出文件中带有当时的筛选条件、操作人、异常数量，便于审计追查 |
| **筛选条件持久化** | 上次使用的盘点状态筛选条件保存在 config，关掉重开自动恢复 |

### 角色权限

| 角色 | 新建盘点 | 填写盘点 | 完成盘点 | 查看全部盘点 | 查看自有相关 | 导出盘点 |
|------|----------|----------|----------|-------------|-------------|---------|
| **管理员** `admin` | ✅ | ✅（全部字段） | ✅ | ✅ | — | ✅ |
| **验收人** `wangwu` / `zhaoliu` | ❌ | ✅（仅状态/位置/备注） | ❌ | ✅ | — | ✅ |
| **借用人** `zhangsan` / `lisi` | ❌ | ❌ | ❌ | ❌ | ✅（仅自己借用过的设备） | ❌ |

## 七、设备交接复核（核验链路追踪）

> 本节为**可直接照着操作的验收指引**。目标：把「借出、归还、维修后交回、冻结解除」四类动作串成可追踪的核验链路，每条记录关联原始业务单、最近盘点结论和交接备注，借用人可确认或提异议，管理员完成最终复核。数据落到 SQLite（`data/handover_records.db`），重启后列表、草稿备注、已完成记录全部恢复。

---

### 7.1 页面入口

启动程序 → 登录后在主界面**右侧 Notebook 选项卡栏**，从左至右依次为：`借用记录` → `维修保养` → `月度盘点` → **`交接复核`** → `操作日志`。点击 **「交接复核」** 标签即可进入。

界面结构从上到下：
1. **筛选行**（5 个下拉/输入 + 应用/重置按钮）
2. **操作按钮行**（右侧：新建交接、查看详情、我（借用人）确认/异议、完成交接、导出选中）
3. **交接记录列表**（Treeview，支持多选，不同状态有不同底色：待确认=白、已确认=浅绿、有异议=浅红、已完成=浅灰）
4. **状态栏**（显示当前筛选后的记录总数）

### 7.2 四类交接动作的状态前置条件

创建交接时系统会自动校验设备状态，**冲突时弹窗明确提示，设备状态保持不变，不会静默覆盖**：

| 交接动作 | 允许的设备状态 | 冲突时提示示例 |
|---------|---------------|--------------|
| **借出** `BORROW_OUT` | 仅 `可借出`（AVAILABLE） | 「设备当前状态为『已借出』，不能发起『借出』交接，请先完成归还流程」 |
| **归还** `RETURN_BACK` | 仅 `已借出`（BORROWED） | 「设备当前状态为『可借出』，不能发起『归还』交接」 |
| **维修后交回** `MAINTENANCE_BACK` | 仅 `维修中`（MAINTENANCE） | 「设备当前状态不是『维修中』，不能发起『维修后交回』交接」 |
| **冻结解除** `FREEZE_RELEASE` | 仅 `异常冻结`（FROZEN） | 「设备当前状态不是『异常冻结』，不能发起『冻结解除』交接」 |

> 以上校验在**创建交接**和**完成交接**两个环节都会执行，任一处冲突即拒绝操作。

### 7.3 管理员操作流程（登录账号：`admin`）

#### 步骤 1：新建交接
1. 点击顶部 **「新建交接」** 按钮 → 弹出对话框
2. 依次填写：
   - **设备**：从下拉列表选择（模糊搜索设备名或 ID）
   - **交接动作**：`借出` / `归还` / `维修后交回` / `冻结解除`
   - **关联业务单 ID**（可选）：借用记录 ID（如 `REC-20260601-xxxx`）或维修记录 ID
   - **目标持有人**（仅借出动作时必填）：选择交接后的持有人
   - **管理员备注**：正式说明文字（会随导出公开可见）
   - **草稿备注**：工作笔记（仅管理员在详情中可见，不会随导出公开）
3. 点击 **「创建」**
   - ✅ 成功：自动跳回列表，新记录出现在顶部（状态=「待确认」）
   - ❌ 冲突：弹出上一节表格中的红色提示，**设备状态保持不变**

#### 步骤 2：筛选待处理记录
在筛选行依次设置条件，点击 **「应用筛选」**：
- **设备ID/名称**：输入关键词模糊匹配（如输入「投影仪」命中所有投影仪）
- **当前持有人**：选择持有人姓名（如「张三」）
- **业务状态**：`全部` / `借出中` / `归还验收中` / `已归还` / `异常冻结` / `可借出` / `维修中`
- **交接状态**：`全部` / `待确认` / `已确认` / `有异议` / `已完成`
- **交接动作**：`全部` / `借出` / `归还` / `维修后交回` / `冻结解除`

> 筛选条件自动保存到 `data/config.json` 的 `last_handoff_filter`，关闭程序重开后自动恢复上次筛选。点击 **「重置」** 清空。

#### 步骤 3：查看详情（含原始业务单 + 最近盘点结论）
1. 选中一条交接记录 → 点击 **「查看详情」**
2. 详情对话框分 4 个区块，**验收时逐项核对**：

| 区块 | 展示内容 |
|------|---------|
| **① 交接概要** | 设备ID/名称、交接动作、当前持有人、目标持有人、业务状态、创建时间、创建人 |
| **② 关联业务单** | 若创建时填写了关联业务单 ID：<br>• 借用记录 → 展示借用人、借出时间、预计归还、实际归还、状态、各环节操作员<br>• 维修记录 → 展示维修类型、送修时间、完成时间、维修人、费用、备注 |
| **③ 最近盘点结论** | 自动抓取该设备**最近一次已完成盘点**的结论：<br>• 盘点结果（正常/损坏/丢失/位置错误/配件缺失/其他）<br>• 实际存放位置、缺失配件、填写人、填写时间、备注<br>• 若无盘点历史，显示「该设备暂无已完成的盘点记录」 |
| **④ 借用人确认信息** | 借用人是否确认、确认/异议时间、确认人、确认备注、**异议原因**（若有） |

3. 在详情中可执行的操作（仅「待确认」或「有异议」状态）：
   - 修改 **管理员备注** 和 **草稿备注** → 点击 **「保存草稿」**
   - 填写 **最终结论**（必填）→ 点击 **「完成交接」**

#### 步骤 4：完成交接
1. 方式 A：在详情对话框填写最终结论后点击 **「完成交接」**
2. 方式 B：在列表选中一条「已确认」记录 → 点击顶部 **「完成交接」** → 输入最终结论
3. 成功后：
   - 记录状态变为 **「已完成」**（列表底色变灰）
   - 自动记录 `completed_by`（当前登录用户名）和 `completed_at`（完成时间）
   - 不能再编辑

### 7.4 借用人操作流程（登录账号：`zhangsan` 或 `lisi`）

借用人登录后：
- 列表**只显示与自己相关**的交接（当前持有人=自己 或 目标持有人=自己）
- 按钮 **「新建交接」「完成交接」「导出选中」** 为灰色禁用
- 不能修改管理员备注、不能查看他人交接、不能导出全量数据

#### 确认交接
1. 选中一条「待确认」的交接 → 点击 **「我（借用人）确认/异议」**

3. 在 **「确认备注」** 输入框填写意见（可选）→ 点击 **「确认交接」**
4. 成功后记录状态变为 **「已确认」**（列表底色变绿）

#### 提出异议
1. 同样打开「我（借用人）确认/异议」对话框
2. 点击 **「提出异议」** → **必须填写异议原因**（留空会提示「提出异议必须填写原因」）

## 八、失败路径验证

| 失败场景 | 触发方式 | 预期结果 |
|----------|----------|----------|
| 已借出设备重复借出 | 选中一台"已借出"设备点击"借出登记" | 弹窗提示"已借出，不能再次借出" |

## 九、批量导入借用记录（CSV / JSON）

用于线下补录历史借用记录，仅 **管理员** 和 **验收人** 可用（借用人看不到此功能）。

### 操作步骤
1. 以管理员或验收人身份登录，右侧记录面板点击 **"批量导入"**
2. 选择一个 `.csv` 或 `.json` 文件（默认打开上次导入目录）
3. 程序先弹出 **预检窗口**，列出：
   - 总记录数 / 可导入数
   - 字段缺失、设备不存在、设备状态冲突、借用人不存在、重复记录等各类问题数
   - 逐条问题明细（行号、问题类型、说明）
   - **只要存在任何一类问题，【确认导入】按钮会被禁用**，必须修正文件后重试
4. **仅当所有记录全部通过预检** 时，才可点击 **"确认导入"**，整批写入数据库；若中途出现任何异常，**整批自动回滚**（不留半条记录，设备状态、记录历史保持不变）

### 导入文件格式

**必填字段**：`device_id`、`borrower_id`、`borrow_time`

**可选字段**：`device_name`、`borrower_name`、`borrower_department`、`expected_return_time`、`actual_return_time`、`status`、`check_out_operator`、`check_in_operator`、`inspect_operator`、`close_operator`、`inspect_remark`、`remark`

**status 取值**：`借出中` / `归还验收中` / `已归还` / `异常冻结`（不填默认为 `借出中`）

#### CSV 示例
```csv
device_id,borrower_id,borrow_time,expected_return_time,status,remark
abc12345,zhangsan,2026-05-20 09:00:00,2026-05-25 18:00:00,已归还,客户演示
def67890,lisi,2026-06-01 14:00:00,2026-06-03 18:00:00,借出中,培训使用
```

#### JSON 示例
```json
[
  {
    "device_id": "abc12345",
    "borrower_id": "zhangsan",
    "borrow_time": "2026-05-20 09:00:00",
    "expected_return_time": "2026-05-25 18:00:00",
    "status": "已归还",
    "remark": "客户演示"
  }
]
```

### 导入行为说明
- **全部合法才可导入**：只要文件中任意一条记录存在字段缺失、设备不存在、设备状态冲突、借用人不存在或重复记录问题，**整批全部拒绝写入**，不会把"看起来合法"的那部分单独落库，也不会改动任何设备状态、记录历史或导入摘要
- 仅当所有记录全部通过预检时，才会提交事务；成功导入会同步更新对应设备的状态，并为每条记录生成一条"批量导入"的状态历史
- 导入过程中若出现任何异常（含 IO / 持久化故障），会自动触发 **整批回滚**，保证不会留下半条记录
- 程序会保存上次导入的 **目录、格式、预检摘要** 到配置文件，重启后仍可读取（即便那次导入最终被拒绝，预检摘要依然保留以便排查）
- 每次导入（无论成功与否）都会写入操作日志（`data/import_logs.json`），包含：操作者、角色、时间、文件路径/格式、成功/失败数量、失败原因

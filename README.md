# 本地设备借用归还验收管理系统

一个基于 Python + Tkinter 的桌面 GUI 应用，用于管理投影仪、录音笔等设备的借出、归还和异常冻结流程。

---

## 一、启动步骤

### 环境要求
- Python 3.8 及以上（Tkinter 为 Python 标准库，无需额外安装）

### 运行方式

**方式 1：直接双击运行（推荐）**
```
双击 run.bat
```

**方式 2：命令行运行**
```bash
cd d:\workSpace\AI__SPACE\zzz-00019
python app.py
```

首次启动时，程序会自动在 `data/` 目录下生成以下 JSON 持久化文件并填充样例数据：

| 文件 | 作用 |
|------|------|
| `data/devices.json` | 设备清单（状态、配件等） |
| `data/borrowers.json` | 借用人信息 |
| `data/records.json` | 借用记录与状态历史 |
| `data/users.json` | 用户账号与角色 |
| `data/config.json` | 常用导出目录、上次登录用户 |

关闭程序后数据会自动保存，下次打开仍可查看。

## 三、主流程说明

### 1. 借出登记
1. 左侧设备列表中选中一台**可借出**状态的设备
2. 点击 **"借出登记"** 按钮
3. 选择借用人 → 填写预计归还时间 → 核对配件（必备配件未勾选会警告）→ 填写备注
4. 确认后：设备状态变为 **已借出**，生成一条 **借出中** 的记录

### 2. 提交归还
1. 右侧记录列表中选中一条**借出中**的记录
2. 点击 **"提交归还"**
3. 勾选当前实际归还的配件 → 填写备注
4. 提交后：记录状态变为 **归还验收中**，设备同步变为 **验收中**

### 3. 归还验收
1. 以**验收人**或**管理员**身份登录
2. 选中一条**归还验收中**的记录，点击 **"验收"**
3. 核对归还配件：
   - 若有**必备配件缺失**：记录和设备自动进入 **异常冻结** 状态
   - 配件齐全：记录变为 **已归还**，设备恢复为 **可借出**
   - 可点击 **"强制通过"** 忽略缺失配件完成验收

### 4. 关闭冻结记录（异常处理）
- **借用人不能关闭冻结记录**（界面按钮禁用 + 业务层二次校验）
- 以**验收人**或**管理员**身份：选中**异常冻结**的记录 → 点击 **"关闭冻结"** → 填写处理说明
- 关闭后：记录变为 **已归还**，设备恢复为 **可借出**

### 5. 查看状态历史
选中任意一条借用记录 → 点击 **"查看历史"**，可看到每次状态变更的：
- 时间、原状态、新状态
- 操作人、操作人角色
- 变更说明/备注

## 四、临期 / 逾期提醒

在右侧 **"借用记录"** 面板的顶部，新增了筛选和提醒配置区域：

### 操作入口
1. 启动程序后，在右侧借用记录列表的顶部即可看到：
   - **筛选按钮组**：`全部` / `临期` / `逾期` / `已归还`
   - **提醒天数设置**：数字输入框 + `应用` 按钮
   - **当前筛选状态**：显示「显示 X/Y 条（筛选类型）」，空结果时会提示「该筛选下无记录」

### 功能说明
| 功能 | 说明 |
|------|------|
| **筛选：全部** | 默认视图，显示所有可见记录 |
| **筛选：临期** | 仅显示：未归还、且预计归还时间距离当前 ≤ 提醒天数的记录 |
| **筛选：逾期** | 仅显示：未归还、且预计归还时间早于当前时间的记录 |
| **筛选：已归还** | 仅显示状态为「已归还」的记录 |
| **提醒列标记** | 列表新增「提醒」列：⏰ 临期（橙色背景）/ ⚠ 逾期（红色背景）/ 空白（正常） |
| **提醒天数** | 默认 3 天；输入 1~365 之间的整数并点击「应用」即可全局生效 |
| **切换保留选中** | 在不同筛选之间切换时，当前在新筛选中仍存在的已选中记录会被自动恢复选中，不会丢失 |
| **导出沿用筛选** | 点击「导出选中」时，仅会导出当前筛选视图下实际被选中的记录，并把筛选类型、提醒天数、操作人等条件写入导出文件（CSV 注释行 / JSON `filter_info` 字段） |

### 角色权限
| 角色 | 查看范围 | 修改提醒天数 |
|------|----------|-------------|
| **管理员** `admin` | 全部借用记录 | ✅ 可修改（1~365 天） |
| **验收人** `wangwu` / `zhaoliu` | 全部借用记录 | ✅ 可修改（1~365 天） |
| **借用人** `zhangsan` / `lisi` | 仅本人的借用记录 | ❌ 不可修改（输入框和按钮为灰色禁用） |

> 提醒天数配置保存在 `data/config.json` 的 `reminder_days` 字段中，关掉程序再打开依然生效。

### 判定规则
- **逾期**：状态非「已归还」 **且** `预计归还时间 < 当前时间`
- **临期**：状态非「已归还」 **且** `当前时间 ≤ 预计归还时间 ≤ 当前时间 + 提醒天数`
- 已归还的记录、或未填写预计归还时间的记录，永远不会被判为临期或逾期

## 五、维修 / 保养（暂停借用）

当设备需要定期保养、故障维修时，可将其登记为「维修中」，在此期间**不能被借出，也不能通过批量导入变成借出中/验收中**。维修完成或无需维修时，可通过「撤销送修」恢复原状态。

### 操作入口

#### 送修登记（仅管理员可用）
1. 在左侧**设备列表**中选中一台状态为 **「可借出」** 或 **「异常冻结」** 的设备
2. 点击设备面板下方的 **「送修/保养」** 按钮
3. 在弹出的对话框中填写：
   - **维修/保养原因**（必填）
   - **预计恢复时间**（可选，默认按「默认维修天数」自动推算）
   - **经办人**（自动填充当前登录用户，可修改）
4. 确认后：
   - 设备状态变为 **「维修中」**（列表中以紫色标记）
   - 生成一条维修日志，记录送修前状态、原因、时间、经办人等
   - 同时生成「借用/归还快照」，用于后续判断能否撤销

#### 撤销送修（仅管理员可用）
1. 在左侧**设备列表**中选中一台**维修中**的设备
2. 点击设备面板下方的 **「撤销送修」** 按钮
3. 对话框会显示当前维修信息，并自动检测：
   - ✅ 送修登记后**没有任何新的借用/归还记录发生变化** → 可撤销
   - ❌ 送修登记后**有新的借用/归还记录发生变化** → 按钮禁用并给出提示
4. 填写撤销说明后确认：
   - 设备状态**恢复为送修前的状态**（「可借出」或「异常冻结」）
   - 维修记录状态变为「已撤销」，记录撤销时间与说明

#### 维修记录查看与导出（管理员 / 验收人可用）
1. 切换到中间/右侧的 **「维修记录」** 面板
2. 顶部筛选区域：
   - **设备ID**：输入精确设备ID筛选
   - **状态**：`全部` / `进行中` / `已撤销`
   - **送修时间起 / 止**：按时间范围筛选
   - 点击 **「应用筛选」** 生效，点击 **「重置」** 清空条件
3. 列表中选中一条或多条记录 → 点击 **「导出选中」** → 选择 `.csv` 或 `.json`
   - CSV 首行会以 `#` 注释形式写入本次筛选条件（设备、状态、时间范围等）
   - JSON 顶层包含 `export_time`、`records`、`filter_info` 三个字段

> 借用人登录时**看不到**「送修/保养」「撤销送修」按钮，也**看不到**「维修记录」面板。

### 功能说明

| 功能 | 说明 |
|------|------|
| **送修资格状态** | 仅「可借出」或「异常冻结」的设备可送修；「已借出」「验收中」「维修中」不可 |
| **进行中借用拦截** | 设备存在进行中的借用记录（借出中/验收中）时，不能送修，需先完成归还流程 |
| **借出拦截** | 维修中的设备点击「借出登记」会报错：「正在维修/保养中，不能借出」 |
| **批量导入拦截** | 维修中的设备无法被批量导入为「借出中」或「验收中」状态，预检会识别为设备状态冲突 |
| **删除拦截** | 维修中的设备不能被删除，需先撤销或等待维修完成 |
| **撤销条件** | 仅管理员可操作，且送修登记后**不能有任何借用/归还记录的状态或实际归还时间变化**（通过快照对比判断） |
| **撤销恢复** | 撤销后设备恢复为送修前状态（可借出 / 异常冻结），不会强制变成可借出 |
| **默认维修天数** | 默认 7 天；管理员可在业务层调用 `set_default_maintenance_days()` 修改，保存进 config |
| **筛选条件持久化** | 上次使用的维修记录筛选条件（设备ID、状态、时间范围）保存在 config，关掉重开仍自动填充 |

### 角色权限

| 角色 | 送修登记 | 撤销送修 | 查看维修记录 | 导出维修记录 |
|------|----------|----------|-------------|-------------|
| **管理员** `admin` | ✅ | ✅ | ✅ | ✅ |
| **验收人** `wangwu` / `zhaoliu` | ❌ | ❌ | ✅ | ✅ |
| **借用人** `zhangsan` / `lisi` | ❌ | ❌ | ❌（面板隐藏） | ❌ |

> 维修日志保存在 `data/maintenance_logs.json`，每条记录包含：维修记录ID、设备ID/名称、送修前状态、原因、预计恢复时间、经办人/角色、送修时间、结束时间、状态（进行中/已撤销）、撤销说明。

## 六、月度盘点

用于定期核对设备的实际状态与系统记录是否一致，支持按筛选范围或手动指定设备创建盘点，区分草稿 / 进行中 / 已完成三种状态，已完成盘点支持按筛选条件导出 CSV / JSON。

### 操作入口

切换到主界面最右侧的 **「月度盘点」** 面板即可使用。

#### 1. 新建盘点（仅管理员可用）
1. 点击盘点面板顶部的 **「新建盘点」** 按钮
2. 在弹出的对话框中填写：
   - **盘点标题**（必填）：如「2026 年 6 月全量盘点」
   - **备注**（可选）：盘点说明
3. **选择盘点范围**（两种方式二选一，优先手动指定）：
   - **方式 A：按筛选条件自动匹配**
     - 设备类别：`全部` / `投影仪` / `录音笔` / `摄像头`
     - 设备状态：`全部` / `可借出` / `已借出` / `验收中` / `维修中` / `异常冻结`
     - 关键字：按设备名称、型号、序列号模糊匹配
     - 点击 **「预览匹配数」** 可实时查看符合条件的设备数量
   - **方式 B：手动多选指定设备**
     - 直接在左侧设备列表中 Ctrl / Shift 多选，点击 **「使用当前选中」** 即可锁定手动范围
4. 点击 **「确认创建」**
   - 创建后盘点状态为 **「草稿」**，可稍后继续填写
   - 盘点快照会立即记录每台设备的系统原状态（作为后续核对基准）

#### 2. 逐台填写盘点结果（管理员 / 验收人可用）
1. 在盘点列表中选中一条 **草稿** 或 **进行中** 的盘点
2. 下方明细列表会显示该盘点涉及的所有设备
3. 选中一台未填写的设备 → 点击 **「填写盘点」** 按钮
4. 填写对话框中包含：
   - **系统原状态**：只读，显示创建盘点时的快照
   - **业务冲突警告**：若设备处于已借出 / 验收中 / 维修中 / 异常冻结，顶部会出现红色提示，且实际状态下拉**被锁定为原状态**（防止盘点覆盖业务状态）
   - **实际状态**：无冲突时可下拉选择，有冲突时固定显示原状态
   - **实际存放位置**：文本输入
   - **缺失配件**：勾选本次盘点发现缺失的配件
   - **盘点结果**：`正常` / `丢失` / `损坏` / `位置错误` / `配件缺失` / `其他异常`
   - **备注**：补充说明
5. 确认后：
   - 该盘点自动变为 **「进行中」** 状态
   - 记录填写人与填写时间

#### 3. 保存草稿 & 继续填写
- 盘点未全部填写时关闭程序，下次打开仍可在盘点列表中看到 **「草稿」** 或 **「进行中」** 的记录
- 选中后直接在明细中继续填写即可，不会丢失已填内容
- **草稿**和**已完成**盘点在列表中通过颜色和状态列明确区分，不会混在一起

#### 4. 完成盘点（仅管理员可用）
1. 选中一条进行中的盘点 → 点击 **「完成盘点」**
2. 若仍有未填写的设备，会弹出警告提示未填数量，可选择继续或取消
3. 填写完成说明（可选）→ 确认
4. 完成后：
   - 盘点状态变为 **「已完成」**，不能再修改或填写
   - 自动统计异常数量（盘点结果 ≠ 正常的设备数）

#### 5. 查看历史盘点 & 详情（管理员 / 验收人可用）
- 盘点列表默认按创建时间倒序排列，可看到全部草稿 / 进行中 / 已完成记录
- 使用顶部 **状态筛选**（全部 / 草稿 / 进行中 / 已完成）+ **应用筛选 / 重置** 可快速过滤
- 选中任意盘点 → 点击 **「查看详情」**：
  - 顶部显示盘点概要（标题、状态、设备总数、异常数、创建/完成时间、操作人、筛选条件）
  - 下方为明细列表，**异常项以橙红色背景高亮**
  - 明细列：设备ID / 设备名称 / 系统原状态 / 实际状态 / 盘点结果 / 实际位置 / 缺失配件 / 填写人 / 备注

#### 6. 导出已完成盘点（管理员 / 验收人可用）
1. 选中一条 **已完成** 的盘点 → 点击 **「导出选中」**
2. 选择保存路径（默认打开已配置的导出目录），可选 `.csv` 或 `.json`
3. 导出内容：
   - **CSV**：
     - 文件首行以 `#` 注释形式写入：盘点标题、状态、导出时间、导出操作人/角色、筛选条件、异常数量、总设备数
     - 数据表列：设备ID / 设备名称 / 系统原状态 / 实际状态 / 盘点结果 / 实际存放位置 / 缺失配件 / 填写人 / 填写时间 / 备注
   - **JSON**：
     - 顶层字段：`export_time` / `export_operator` / `export_operator_role` / `exception_count` / `total_devices` / `session`
     - `session` 内包含完整盘点信息（标题、状态、筛选条件、创建/完成时间、所有 items）

> 草稿 / 进行中状态的盘点**不允许导出**，会弹出提示。

#### 7. 借用人视角（仅查看自己借用相关的结论）
- 借用人登录后，盘点面板只显示 **已完成** 的盘点
- 每条盘点的明细中，**仅包含该借用人曾经借用过的设备**，其他设备全部被过滤掉
- 借用人**不能**新建盘点、填写盘点、完成盘点，这些按钮为灰色禁用状态

### 功能说明

| 功能 | 说明 |
|------|------|
| **草稿持久化** | 未完成的盘点（草稿/进行中）保存在 `data/inventory_sessions.json`，跨重启完整保留 |
| **状态分离** | 草稿 / 进行中 / 已完成在列表中颜色区分（草稿灰色、进行中蓝色、已完成绿色），不会混淆 |
| **冲突保护（核心）** | 设备若处于「已借出 / 验收中 / 维修中 / 异常冻结」任一活跃业务状态，填写盘点时**实际状态被锁定为原状态**，不能改为其他状态，避免盘点覆盖借出/维修等真实业务 |
| **快照不覆盖业务** | 盘点仅记录自己的快照和结论，**不会修改** `devices.json` 中的任何设备状态 |
| **按筛选导出** | 导出文件中带有当时的筛选条件、操作人、异常数量，便于审计追查 |
| **筛选条件持久化** | 上次使用的盘点状态筛选条件保存在 config，关掉重开自动恢复 |

### 角色权限

| 角色 | 新建盘点 | 填写盘点 | 完成盘点 | 查看全部盘点 | 查看自有相关 | 导出盘点 |

## 六、数据导出（CSV / JSON）

导出内容与界面列表保持一致：

### 导出设备清单
左侧设备面板 → 点击 **"导出"** → 选择 `.csv` 或 `.json`
- CSV 包含：设备ID、名称、类别、型号、序列号、状态、配件、备注、创建时间

### 导出借用记录
右侧记录列表 → **多选**记录 → 点击 **"导出选中"** → 选择 `.csv` 或 `.json`
- CSV 包含：记录ID、设备、借用人、借出/归还时间、状态、**提醒状态**、各环节操作员、备注等；导出时若处于某个筛选视图，文件首行会以 `#` 注释形式写入筛选类型、提醒天数、操作人等追查信息
- JSON 导出：顶层含 `export_time`、`records`（完整对象，含配件核对详情、状态历史）、`filter_info`（本次筛选条件）三个字段

> 顶部"导出目录"显示状态：【可写】(绿色) / 【不可写】(红色)。目录不可写时任何导出操作都会被拒绝，且不会改动选中数据。

## 七、批量导入借用记录（CSV / JSON）

用于线下补录历史借用记录，仅 **管理员** 和 **验收人** 可用（借用人看不到此功能）。

### 操作步骤
1. 以管理员或验收人身份登录，右侧记录面板点击 **"批量导入"**
2. 选择一个 `.csv` 或 `.json` 文件（默认打开上次导入目录）
3. 程序先弹出 **预检窗口**，列出：
   - 总记录数 / 可导入数
   - 字段缺失、设备不存在、设备状态冲突、借用人不存在、重复记录等各类问题数
   - 逐条问题明细（行号、问题类型、说明）
   - **只要存在任何一类问题，【确认导入】按钮会被禁用**，必须修正文件后重试
4. **仅当所有记录全部通过预检** 时，才可点击 **"确认导入"**，整批写入数据库；若中途出现任何异常，**整批自动回滚**（不留半条记录，设备状态、记录历史保持不变）

### 导入文件格式

**必填字段**：`device_id`、`borrower_id`、`borrow_time`

**可选字段**：`device_name`、`borrower_name`、`borrower_department`、`expected_return_time`、`actual_return_time`、`status`、`check_out_operator`、`check_in_operator`、`inspect_operator`、`close_operator`、`inspect_remark`、`remark`

**status 取值**：`借出中` / `归还验收中` / `已归还` / `异常冻结`（不填默认为 `借出中`）

#### CSV 示例
```csv
device_id,borrower_id,borrow_time,expected_return_time,status,remark
abc12345,zhangsan,2026-05-20 09:00:00,2026-05-25 18:00:00,已归还,客户演示
def67890,lisi,2026-06-01 14:00:00,2026-06-03 18:00:00,借出中,培训使用
```

#### JSON 示例
```json
[
  {
    "device_id": "abc12345",
    "borrower_id": "zhangsan",
    "borrow_time": "2026-05-20 09:00:00",
    "expected_return_time": "2026-05-25 18:00:00",
    "status": "已归还",
    "remark": "客户演示"
  }
]
```

### 导入行为说明
- **全部合法才可导入**：只要文件中任意一条记录存在字段缺失、设备不存在、设备状态冲突、借用人不存在或重复记录问题，**整批全部拒绝写入**，不会把"看起来合法"的那部分单独落库，也不会改动任何设备状态、记录历史或导入摘要
- 仅当所有记录全部通过预检时，才会提交事务；成功导入会同步更新对应设备的状态，并为每条记录生成一条"批量导入"的状态历史
- 导入过程中若出现任何异常（含 IO / 持久化故障），会自动触发 **整批回滚**，保证不会留下半条记录
- 程序会保存上次导入的 **目录、格式、预检摘要** 到配置文件，重启后仍可读取（即便那次导入最终被拒绝，预检摘要依然保留以便排查）
- 每次导入（无论成功与否）都会写入操作日志（`data/import_logs.json`），包含：操作者、角色、时间、文件路径/格式、成功/失败数量、失败原因
